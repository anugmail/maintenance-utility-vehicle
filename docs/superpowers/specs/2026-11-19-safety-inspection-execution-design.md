# ออกแบบ: Safety Inspection ส่วนดำเนินการตรวจ

แผนเดินทางจ้างตรวจ และการบันทึกผลการตรวจ ปจ.2 รายคัน

- วันที่: 19 พ.ย. 2569
- branch: `feat/safety-inspection-execution` (แตกจาก `main` 4cc29f5)
- สถานะ: รอเจ้าของงานอนุมัติ

ในเอกสารนี้ "เคาะแล้ว" คือสิ่งที่เจ้าของงานบอกเอง ส่วน "ผู้เขียนเลือก" คือสิ่งที่ผู้เขียนเติมเพื่อให้ทำต่อได้ เจ้าของงานแก้ได้ทุกข้อ รวมไว้ในหัวข้อ 9

## 1. ที่มาและเหตุผล

ยานพาหนะติดตั้งเครนหรือกระเช้าต้องตรวจสอบความปลอดภัยตามรอบ (หลักเกณฑ์ยานพาหนะ 2569 ข้อ 14 · JO 7.3.3) ต้นแบบตอนนี้มีแค่หน้า "การตรวจ ปจ.2" (S26 · `/safety/`) ที่อัปโหลดผลรายคันย้อนหลัง ไม่มีแผน และไม่รู้ว่าการตรวจแต่ละครั้งเกิดจากงานไหน

งาน Safety Inspection แบ่งเป็น 3 ส่วน ทำคนละคน คนละ branch แล้ว merge เข้า `main`

| ส่วน | เนื้อหา | อยู่ในเอกสารนี้ |
|---|---|---|
| สร้างแผน | แผนตรวจประจำปี หรือประจำ 6 เดือน | ไม่อยู่ |
| ดำเนินการตรวจ | สร้างแผนเดินทาง แล้วบันทึกผลรายคัน | อยู่ |
| ปิดงาน | ปิดแผนหลังตรวจครบ | ไม่อยู่ |

ส่วนดำเนินการตรวจเริ่มหลังแผนตรวจอนุมัติแล้ว ทำงานแบบเดียวกับแผนเดินทางของแผนบำรุงรักษาตามวาระ (S6 S9 S7 S8 S10) ต่างกันที่ field ซึ่งปรับให้เข้ากับการตรวจ ปจ.2

## 2. เป้าหมาย สิ่งที่ไม่ทำ และสิ่งที่ห้ามพลาด

**เป้าหมาย**

1. ผู้ดำเนินการสร้างแผนเดินทางจ้างตรวจจากยานพาหนะของแผนตรวจที่อนุมัติแล้ว ส่งอนุมัติ และแก้ไขเมื่อถูกส่งกลับ
2. ผู้อนุมัติพิจารณาแผนเดินทางจากคิวเดิม "แผนเดินทางรออนุมัติ"
3. กรย. และผู้ดูแลยานพาหนะได้รับแจ้งเตือนเมื่อแผนเดินทางอนุมัติ
4. ผู้ดำเนินการบันทึกผลการตรวจ ปจ.2 รายคันจากหน้ารายละเอียดแผนเดินทาง บันทึกแล้วคันนั้นปิดงาน และหน้า "การตรวจ ปจ.2" อัปเดตวันครบกำหนดครั้งถัดไป

**ไม่ทำใน branch นี้**

- การสร้าง แก้ไข อนุมัติแผนตรวจ (ส่วนสร้างแผน)
- การปิดแผน การรับทราบผลของผู้ดูแลยานพาหนะ และแบบประเมิน (ส่วนปิดงาน)
- บทบาทผู้รับจ้างเข้ามาบันทึกผลเอง
- ปุ่มส่งออกในหน้ารายละเอียดแผนเดินทาง
- การแก้หน้า "การตรวจ ปจ.2" (S26) และ popup เดิมของหน้านั้น
- หน้า `/guide/` ของเรื่องนี้
- ไฟล์ userflow จอ Figma และการ์ด FLO (ดูหัวข้อ 10)

**ห้ามพลาด**

- หน้าของแผนบำรุงรักษา (S6 ถึง S10 S12 S23 S25 และแดชบอร์ด S4 S24) ต้องทำงานเหมือนเดิม และต้องไม่แสดงแผนเดินทางจ้างตรวจปนเข้าไป
- ห้ามออกแบบ component เอง ทุกชิ้นต้องเป็น component ของไลบรารีตาม `CLAUDE.md`
- ห้ามแก้ไฟล์ที่ใช้ร่วมกันเกินจำเป็น เพราะอีกสอง branch จะ merge เข้า `main` เหมือนกัน

## 5. สิ่งที่เจ้าของงานเคาะแล้ว

- การตรวจ Safety มีแต่การจ้างตรวจ ไม่มีดำเนินการเอง
- แผนเดินทางเหมือนแผนเดินทางของแผนบำรุงรักษา ต่างกันที่ field
- ตารางยานพาหนะในหน้ารายละเอียดมีคอลัมน์ตามภาพอ้างอิง 1: ทะเบียน · สังกัด · ผู้ครอบครอง/เบอร์ติดต่อ · วาระ · วันที่ตรวจ · ผล ปจ.2 · สถานะงาน · ปุ่มของแถว
- หน้าบันทึกผลเป็น popup ตามภาพอ้างอิง 2: วันที่ตรวจ · ค่าจ้างตรวจคันนี้ (บาท) · ผลการตรวจ 4 ตัวเลือก ผ่าน ไม่ผ่าน ระงับ ตรวจไม่ได้ · เอกสารการตรวจ ปจ.2 (ต้องแนบ) · กล่องข้อความบอกผลของการบันทึก · ปุ่ม ยกเลิก บันทึก
- ข้อความในกล่องใช้ "ยานพาหนะคันนี้" ไม่ใช่ "รถคันนี้"
- component ใช้ตามเงื่อนไขเดียวกับต้นแบบบำรุงรักษา ต้องตรงกับไลบรารี ไม่หยิบเอง

ภาพอ้างอิงทั้งสองเป็นภาพที่เจ้าของงานส่งในแชต ไม่มีในรีโป รายละเอียดที่ใช้จากภาพเขียนไว้ในหัวข้อ 6 ครบแล้ว

## 6. การออกแบบ

### 6.1 เส้นทางการทำงาน

```
แผนตรวจ ปจ.2 อนุมัติแล้ว (ของส่วนสร้างแผน ตอนนี้ใช้ข้อมูลจำลอง)
  → ผู้ดำเนินการเปิดหน้าแผนเดินทางของแผนตรวจ → สร้างแผนเดินทาง → ส่งอนุมัติ
  → ผู้อนุมัติ: อนุมัติ หรือ ส่งกลับแก้ไขพร้อมเหตุผล
       ส่งกลับ → ผู้ดำเนินการแก้ไข → ส่งอนุมัติใหม่
       อนุมัติ → แจ้งเตือน กรย. และผู้ดูแลยานพาหนะของแต่ละคัน
  → ผู้ดำเนินการเปิดรายละเอียดแผนเดินทาง → บันทึกผลตรวจทีละคัน
  → คันที่บันทึกแล้ว "ปิดงานแล้ว" และหน้า "การตรวจ ปจ.2" อัปเดตวันครบกำหนด
  → ครบทุกคัน: ส่งต่อให้ส่วนปิดงาน (นอกขอบเขต)
```

### 6.2 หน้าและที่อยู่

| ที่อยู่ | หน้า | เทียบกับของบำรุงรักษา |
|---|---|---|
| `/safety/trips/?plan=<รหัสแผน>` | แผนเดินทางของแผนตรวจ: ยานพาหนะในแผน และรายการแผนเดินทาง | หน้าไตรมาส `/quarter/trips/` |
| `/safety/trips/new/?plan=<รหัสแผน>` | สร้างแผนเดินทาง | `/quarter/trips/new/` |
| `/safety/trips/edit/?trip=<รหัส>` | แก้ไขแผนเดินทางที่ถูกส่งกลับ | `/quarter/trips/edit/` |
| `/safety/trips/detail/?trip=<รหัส>` | รายละเอียดแผนเดินทาง และ popup ผลการตรวจ ปจ.2 | `/trips/detail/` |
| `/approvals/trips/` และ `/approvals/trips/detail/` (หน้าเดิม) | คิวและหน้าตรวจสอบแผนเดินทาง แสดงทั้งสองชนิด | ใช้ร่วม |

เมนู Sidebar ที่ Active ของทุกหน้าใต้ `/safety/` คือ "การตรวจ ปจ.2" ตามที่เป็นอยู่ ไม่เพิ่มเมนูใหม่ ทางเข้าหน้าแผนเดินทางของแผนตรวจระหว่างที่ส่วนสร้างแผนยังไม่ merge คือหน้า `/scenarios/` เมื่อส่วนสร้างแผนมาแล้วจะลิงก์จากหน้ารายละเอียดแผนตรวจ

### 6.3 หน้าแผนเดินทางของแผนตรวจ

โครงเดียวกับหน้าไตรมาสของบำรุงรักษา ตัดส่วนอะไหล่และการเพิ่ม ลบ ย้ายยานพาหนะออก เพราะรายการยานพาหนะเป็นของแผนตรวจ

- หัวหน้า: ชื่อแผนตรวจ และป้ายสถานะแผน
- รายละเอียดแผนตรวจ: ค่าจากข้อมูลจำลองของแผน (ชื่อแผน ช่วงเวลา จำนวนยานพาหนะ)
- "ยานพาหนะในแผน (n)" ตารางดูอย่างเดียว: ทะเบียน · สังกัด · ผู้ครอบครอง/เบอร์ติดต่อ · วาระ · ครบกำหนด · แผนเดินทาง
  - คันที่ยังไม่อยู่ในใบใด: ป้าย "ยังไม่มีแผนเดินทาง"
  - คันที่อยู่ในใบแล้ว: ชื่อแผนเดินทาง บรรทัดรองเป็นวันนัดตรวจของคันนั้น
- "แผนเดินทาง (n)" ตารางรายการใบ คอลัมน์ชุดเดียวกับตารางแผนเดินทางของหน้าไตรมาส และปุ่ม "สร้างแผนเดินทาง"
  - ยานพาหนะทุกคันอยู่ในใบแล้ว ปุ่มสร้างกดไม่ได้
  - กดแถว: อนุมัติแล้ว ไปหน้ารายละเอียด · ส่งกลับแก้ไข ไปหน้าแก้ไข · รออนุมัติ ไม่ไปไหน

### 6.4 ฟอร์มสร้างและแก้ไขแผนเดินทาง

ฟอร์มเดียวกับแผนเดินทางแบบจ้างดำเนินการของบำรุงรักษา (S9) โดยไม่มีตัวเลือกรูปแบบดำเนินการ ไม่มีส่วนพนักงานที่เดินทาง และไม่มีส่วนอะไหล่

| ส่วน | field | บังคับ |
|---|---|---|
| ข้อมูลแผนเดินทาง | ชื่อแผนเดินทาง | บังคับ |
| ผู้รับจ้าง | ผู้รับจ้าง (ค้นหาจากรายชื่อ) | บังคับ |
| | เบอร์โทรผู้รับจ้าง (เติมจากข้อมูลผู้รับจ้าง แก้ได้) | บังคับ |
| | เลขที่สัญญา/ใบสั่งจ้าง | ไม่บังคับ |
| ช่วงวันทำงาน | วันที่เริ่ม · วันที่สิ้นสุด | บังคับ |
| ยานพาหนะในแผนเดินทาง | ตารางตามด้านล่าง และปุ่ม "เพิ่มยานพาหนะ" | อย่างน้อย 1 คัน |

ตารางยานพาหนะในฟอร์ม 8 คอลัมน์

| # | คอลัมน์ | ค่า |
|---|---|---|
| 1 | ทะเบียน | บรรทัดรอง: ประเภทยานพาหนะ และยี่ห้อ/รุ่น |
| 2 | สังกัด | หน่วยงานเจ้าของยานพาหนะ |
| 3 | ผู้ครอบครอง/เบอร์ติดต่อ | ชื่อบรรทัดบน เบอร์บรรทัดรอง ค่าเริ่มต้นจากข้อมูลยานพาหนะ |
| 4 | วาระ | 3 6 หรือ 12 เดือน อ่านจากรายการยานพาหนะของแผนตรวจ (แผนจำลองเติมค่าจากผลล่าสุดของหน้า "การตรวจ ปจ.2" ไม่มีผล = 12 เดือน) |
| 5 | ครบกำหนด | วันครบกำหนดครั้งถัดไปจากหน้า "การตรวจ ปจ.2" บรรทัดรองนับถอยหลัง "เหลือ n วัน" หรือ "เลยกำหนด n วัน" ไม่มีผล = "-" |
| 6 | สถานที่ตรวจ | ค่าเริ่มต้น สำนักงานของสังกัด บรรทัดรองบอกว่าเป็นค่าเริ่มต้นหรือแก้แล้ว |
| 7 | วันนัดตรวจ | ค่าเริ่มต้น ทั้งช่วงวันทำงาน แก้รายคันได้ เปลี่ยนช่วงวันทำงานแล้วกลับเป็นทั้งช่วงใหม่ |
| 8 | ไอคอนแก้ไข · ลบ | แก้ไข: popup แก้ ผู้ครอบครอง เบอร์ติดต่อ สถานที่ตรวจ วันนัดตรวจ · ลบ: เอาออกจากใบนี้ |

- popup "เพิ่มยานพาหนะ" ใช้ตัวเลือกยานพาหนะแบบเดียวกับฟอร์มแผนเดินทางบำรุงรักษา ตัวเลือกคือยานพาหนะของแผนตรวจ คันที่อยู่ในแผนเดินทางจ้างตรวจใบอื่นติ๊กไม่ได้
- ปุ่ม: ย้อนกลับ · ยืนยันการสร้างแผนเดินทาง (หน้าแก้ไข: ส่งอนุมัติใหม่) กดไม่ได้จนช่องบังคับครบ
- หน้าแก้ไขแสดงข้อความแจ้งว่าผู้อนุมัติส่งกลับพร้อมเหตุผลไว้บนสุด
- ข้อความตรวจช่องบังคับ ข้อความยืนยัน และ toast ใช้ชุดเดียวกับฟอร์มแผนเดินทางบำรุงรักษา

### 6.5 อนุมัติและแจ้งเตือน

ใช้หน้าเดิมของแผนเดินทางบำรุงรักษาทั้งคิว หน้าตรวจสอบ และหน้าของ กรย. กับผู้ดูแลยานพาหนะ เมื่อใบเป็นแผนเดินทางจ้างตรวจ ให้ต่างจากเดิมเท่านี้

- ตารางยานพาหนะใช้คอลัมน์ 1 ถึง 7 ของหัวข้อ 6.4 (ดูอย่างเดียว)
- ไม่มีส่วนอะไหล่ของแผนเดินทาง
- ข้อความแจ้งเตือนใช้รูปประโยคเดียวกับของบำรุงรักษา เปลี่ยนคำว่า บำรุงรักษา เป็น ตรวจ ปจ.2
- จำนวนบนป้ายเมนู "แผนเดินทางรออนุมัติ" นับรวมทั้งสองชนิด
- ปุ่ม "ส่งออก" ของหน้าเดิมไม่แสดงเมื่อใบเป็นแผนเดินทางจ้างตรวจ เพราะตัวส่งออกเดิมพิมพ์คอลัมน์และหน้าอะไหล่ของบำรุงรักษา

ขั้นตอน ปุ่มพิจารณา ผลการพิจารณา และ toast เหมือนเดิม

### 6.6 หน้ารายละเอียดแผนเดินทาง

- หัวหน้า: ชื่อแผนเดินทาง และป้าย "อนุมัติแล้ว"
- รายละเอียดแผนเดินทาง: ผู้รับจ้าง · เบอร์โทรผู้รับจ้าง · เลขที่สัญญา/ใบสั่งจ้าง · ช่วงวันทำงาน · ผู้สร้างและวันที่ส่ง อนุมัติ (ชุดเดียวกับใบจ้างของบำรุงรักษา) · ความคืบหน้า · ค่าจ้างตรวจรวม (ผลรวมค่าจ้างของคันที่บันทึกแล้ว)
  - ความคืบหน้าเขียนว่า "ปิดงานแล้ว x/y คัน" ตรงกับคอลัมน์สถานะงาน x นับทุกคันที่บันทึกผลแล้วรวมคันที่ตรวจไม่ได้ y คือทุกคันในใบ ถ้ามีคันที่ตรวจไม่ได้ให้ต่อท้ายว่า "ตรวจไม่ได้ n คัน" ตัวอย่างตามภาพอ้างอิง 1: "ปิดงานแล้ว 3/5 คัน · ตรวจไม่ได้ 1 คัน"
- ส่วน "ยานพาหนะ" ตาราง 8 คอลัมน์ตามภาพอ้างอิง 1

| # | คอลัมน์ | ยังไม่ตรวจ | บันทึกผลแล้ว |
|---|---|---|---|
| 1 | ทะเบียน | ทะเบียน | เหมือนกัน |
| 2 | สังกัด | สังกัด | เหมือนกัน |
| 3 | ผู้ครอบครอง/เบอร์ติดต่อ | ชื่อ บรรทัดรองเบอร์ | เหมือนกัน |
| 4 | วาระ | n เดือน | เหมือนกัน |
| 5 | วันที่ตรวจ | "-" บรรทัดรอง "นัด" ตามด้วยวันนัดตรวจ | วันที่ตรวจที่บันทึก |
| 6 | ผล ปจ.2 | "-" | ป้ายผลอย่างเดียว |
| 7 | สถานะงาน | ป้าย "ยังไม่ตรวจ" | ป้าย "ปิดงานแล้ว" |
| 8 | ปุ่มของแถว | บันทึกผลตรวจ | ดูรายละเอียด |

สีป้าย: ผ่าน Success · ไม่ผ่าน Error · ระงับ Warning (ชุดเดิมของหน้า "การตรวจ ปจ.2") · ตรวจไม่ได้ Warning · ยังไม่ตรวจ Warning · ปิดงานแล้ว Success

ปุ่มของแถว: Table ของไลบรารีบน desktop มีแบบ Action icons เท่านั้น ไม่มีปุ่มข้อความในช่องตาราง จึงใช้ไอคอนแบบเดียวกับหน้า "การตรวจ ปจ.2" คือ ไอคอนอัปโหลดสำหรับบันทึกผลตรวจ และไอคอนดูผลสำหรับดูรายละเอียด ส่วนมือถือใช้ Mobile table item แบบ Action buttons เป็นปุ่มข้อความ "บันทึกผลตรวจ" และ "ดูรายละเอียด" ได้ (ภาพอ้างอิง 1 วาดเป็นปุ่มข้อความบน desktop ซึ่งไลบรารีไม่มี)

ช่องผล ปจ.2: ช่องแบบป้ายของ Table ไลบรารีใส่ได้แต่ป้าย ไม่มีบรรทัดรอง จึงแสดงป้ายผลอย่างเดียว สาเหตุและเอกสารยืนยันของคันที่ตรวจไม่ได้ดูได้จาก popup ดูรายละเอียด (ภาพอ้างอิง 1 วาดบรรทัดรอง "อยู่ระหว่างซ่อม · แนบเอกสารยืนยันแล้ว" ใต้ป้าย ซึ่งไลบรารีไม่มี) ข้อนี้รอเจ้าของงานยืนยัน ดูหัวข้อ 9 ข้อ 4

### 6.7 popup ผลการตรวจ ปจ.2

popup บนหน้ารายละเอียด (มือถือเป็น bottom sheet) โครงและ component ชุดเดียวกับ popup ของหน้า "การตรวจ ปจ.2" (S26)

- หัว: "ผลการตรวจ ปจ.2" บรรทัดรอง: ทะเบียน · รหัสยานพาหนะ · ประเภทยานพาหนะ · วาระ n เดือน

| field | รายละเอียด | บังคับ |
|---|---|---|
| วันที่ตรวจ | เลือกวันเดียว ไม่เกินวันนี้ | บังคับ |
| ค่าจ้างตรวจคันนี้ (บาท) | ตัวเลขทศนิยม 2 ตำแหน่ง | บังคับ ยกเว้นผลตรวจไม่ได้ |
| ผลการตรวจ | เลือก 1 จาก ผ่าน · ไม่ผ่าน · ระงับ · ตรวจไม่ได้ ไม่มีค่าเริ่มต้น | บังคับ |
| สาเหตุ | แสดงเมื่อเลือกตรวจไม่ได้ ข้อความสั้น เช่น อยู่ระหว่างซ่อม | บังคับเมื่อแสดง |
| เอกสารการตรวจ ปจ.2 (ต้องแนบ) | PDF หรือรูปภาพ (JPG PNG) ไฟล์ละไม่เกิน 10 MB สูงสุด 10 ไฟล์ · เมื่อเลือกตรวจไม่ได้ ชื่อช่องเป็น "เอกสารยืนยัน (ต้องแนบ)" | บังคับ |

- วาระไม่มีให้เลือกใน popup ใช้วาระของคันนั้นจากตาราง
- กล่องข้อความ (Alert สี Success) ใต้ช่องเอกสาร แสดงเมื่อเลือกวันที่ตรวจและผลแล้ว
  - ผ่าน ไม่ผ่าน ระงับ: "บันทึกแล้วยานพาหนะคันนี้ปิดงานในแผน ทะเบียน ปจ.2 อัปเดตครบกำหนดครั้งถัดไปเป็น {วันที่ตรวจ + วาระ} (วันที่ตรวจ + {n} เดือน)"
  - ตรวจไม่ได้: "บันทึกแล้วยานพาหนะคันนี้ปิดงานในแผน วันครบกำหนดในทะเบียน ปจ.2 ไม่เปลี่ยน"
- ปุ่ม: ยกเลิก · บันทึก (กดไม่ได้จนช่องบังคับครบ)
- กดบันทึก: toast "บันทึกผลการตรวจ ปจ.2 สำเร็จ" ปิด popup แถวในตารางเปลี่ยนทันที ความคืบหน้าและค่าจ้างตรวจรวมเปลี่ยนตาม
- ผลของการบันทึก
  - ผ่าน ไม่ผ่าน ระงับ: เพิ่มผลหนึ่งครั้งเข้าทะเบียนของหน้า "การตรวจ ปจ.2" (วันที่ตรวจ ผล วาระ เอกสาร) วันครบกำหนดครั้งถัดไป = วันที่ตรวจ + วาระ ตามวิธีคิดเดิมของหน้านั้น
  - ตรวจไม่ได้: เก็บไว้กับแผนเดินทางเท่านั้น ไม่เพิ่มเข้าทะเบียน
- ดูรายละเอียดของคันที่ปิดงานแล้ว: popup เดียวกันแบบดูอย่างเดียว แสดงค่าที่บันทึก ดาวน์โหลดเอกสารได้ มีปุ่ม "ปิด" อย่างเดียว บันทึกแล้วแก้ไม่ได้

### 6.8 สิทธิ์ตามบทบาท

ใช้สิทธิ์ชุดเดียวกับแผนเดินทางของบำรุงรักษาใน `PERMISSIONS.md` แล้วเพิ่มแถวของหน้าใหม่ลงไฟล์นั้น หน่วยงานผู้สร้างแผนทำได้เฉพาะแผนตรวจของหน่วยงานตัวเอง ตามหลักเดียวกับแผนบำรุงรักษา

| บทบาท | หน้าแผนเดินทางของแผนตรวจ และฟอร์ม | รายละเอียดแผนเดินทาง และบันทึกผล |
|---|---|---|
| หน่วยงานผู้สร้างแผน (ผู้ดำเนินการ) | สร้าง แก้ไขใบที่ส่งกลับ | บันทึกผลตรวจ ดูรายละเอียด |
| กบค. | ดูอย่างเดียว | ดูอย่างเดียว |
| ผู้อนุมัติ | ไม่เข้า (ทำงานที่คิวอนุมัติ) | ไม่เข้า |
| กรย. · ผู้ดูแลยานพาหนะ | ไม่เข้า (ดูที่หน้าแผนเดินทางที่อนุมัติแล้ว และรับแจ้งเตือน) | ไม่เข้า |
| ผู้รับจ้าง | ไม่เข้า | ไม่เข้า |

### 6.9 ข้อมูลจำลอง และรอยต่อกับอีกสองส่วน

- **แผนตรวจจำลอง** หนึ่งแผน สถานะอนุมัติแล้ว มียานพาหนะประเภท 09 จากข้อมูลจำลองเดิมประมาณ 8 ถึง 10 คัน หลายสังกัด หลายวาระ รวมคันที่อยู่ในภาพอ้างอิง 1 เท่าที่มีในชุดเดิม อยู่ในไฟล์ของตัวเองไฟล์เดียว เป็นรอยต่อที่ส่วนสร้างแผนจะมาแทน สิ่งที่ส่วนดำเนินการตรวจต้องการจากแผนตรวจมีแค่: รหัสแผน ชื่อแผน สถานะ ช่วงเวลา หน่วยงานผู้สร้างแผน (ใช้ตัดสินสิทธิ์) และรายการยานพาหนะของแผนพร้อมวาระรายคัน
- **หนึ่งคันตรวจหนึ่งครั้งต่อหนึ่งแผนตรวจ** ยานพาหนะคันหนึ่งอยู่ได้ในแผนเดินทางใบเดียวของแผนตรวจนั้น ผลรายคันอ้างด้วยแผนตรวจคู่กับยานพาหนะ และให้เผื่อเพิ่มตัวบอกรอบได้ทีหลังโดยไม่ต้องรื้อ ข้อนี้รอเจ้าของงานยืนยัน ดูหัวข้อ 9 ข้อ 2
- **รายชื่อผู้รับจ้างตรวจ** ชุดใหม่ 3 ถึง 4 ราย (ชื่อ ประเภทที่รับตรวจ เบอร์โทร) แยกจากผู้รับจ้างบำรุงรักษา
- **แผนเดินทางและผลรายคัน** เก็บใน `localStorage` คีย์เดิม ปุ่ม "ล้างข้อมูลจำลอง" ล้างได้ด้วย
- **ชุดตัวอย่างสำหรับหน้า `/scenarios/`** อย่างน้อย: ฟอร์มว่างพร้อมกรอกตัวอย่าง · ใบรออนุมัติ · ใบถูกส่งกลับ · ใบอนุมัติแล้วยังไม่ตรวจ · ใบตรวจไปบางส่วนแบบภาพอ้างอิง 1 (ผ่าน 2 คัน ยังไม่ตรวจ 2 คัน ตรวจไม่ได้ 1 คัน)
- **รอยต่อกับส่วนปิดงาน** ส่วนดำเนินการตรวจให้ค่าที่อ่านได้ต่อแผนตรวจและต่อแผนเดินทาง: จำนวนคันทั้งหมด จำนวนคันที่ปิดงานแล้ว (รวมคันที่ตรวจไม่ได้) จำนวนคันที่ตรวจไม่ได้ ครบทุกคันหรือยัง และค่าจ้างตรวจรวม

## 8. สิ่งที่ปล่อยให้ผู้ทำตัดสิน

- โครงไฟล์ ชื่อไฟล์ ชื่อชนิดข้อมูล และวิธีเก็บแผนเดินทางจ้างตรวจ (รวมรายการเดียวกับของบำรุงรักษาโดยมีตัวบอกชนิด หรือแยกรายการ) ตราบใดที่หน้าบำรุงรักษาไม่แสดงใบจ้างตรวจ และคิวอนุมัติกับหน้าแจ้งเตือนแสดงทั้งสองชนิด
- การนำชิ้นเดิมมาใช้ซ้ำ (ตัวเลือกยานพาหนะ popup แก้ไขยานพาหนะ ชิ้นผลการพิจารณา) หรือเขียนชิ้นคู่ขนานใต้ `/safety/trips/`
- ต้องขึ้นรุ่น `MOCK_V` หรือไม่ ตามกติกาข้อ 5
- ค่าตัวอย่างในข้อมูลจำลอง (ชื่อแผนเดินทาง ชื่อผู้รับจ้าง วันที่ ค่าจ้าง) ให้สมจริงและสอดคล้องกับวันนี้ของต้นแบบ
- ความกว้างคอลัมน์ และการจัดช่องบนมือถือ ตามแบบหน้าที่เทียบเคียง
- คอลัมน์ของ popup เพิ่มยานพาหนะ ให้เลือกจากคอลัมน์ 1 ถึง 5 ของหัวข้อ 6.4 ที่ใส่ได้พอดี

## 9. สิ่งที่ผู้เขียนเลือกเอง เจ้าของงานตรวจตรงนี้

1. ขอบเขต: branch นี้รวมการบันทึกผลรายคันจนคันนั้นปิดงาน ส่วนการปิดแผนเป็นของส่วนปิดงาน
2. **รอยืนยัน** ไม่มีไตรมาส: แผนเดินทางผูกกับแผนตรวจโดยตรง และยานพาหนะหนึ่งคันตรวจหนึ่งครั้งต่อหนึ่งแผนตรวจ (คันวาระ 3 หรือ 6 เดือนจะอยู่ในแผนตรวจของแต่ละรอบ ไม่ตรวจซ้ำในแผนเดียว)
3. ใช้คิวอนุมัติและหน้าแจ้งเตือนเดิมร่วมกับแผนเดินทางบำรุงรักษา และซ่อนปุ่มส่งออกของหน้าเดิมเมื่อเป็นใบจ้างตรวจ
4. **รอยืนยัน** สองจุดที่ภาพอ้างอิง 1 ต่างจากไลบรารี: ปุ่มของแถวบน desktop เป็นไอคอน (มือถือเป็นปุ่มข้อความ) และช่องผล ปจ.2 แสดงป้ายอย่างเดียว สาเหตุของคันที่ตรวจไม่ได้ไปอยู่ใน popup ดูรายละเอียด
5. หัวคอลัมน์ "ผู้ครอบครอง/เบอร์ติดต่อ" ตามภาพอ้างอิง ชื่ออยู่บรรทัดบน (ต้นแบบบำรุงรักษาใช้ "เบอร์ติดต่อ" เบอร์อยู่บรรทัดบน และเรียกบทบาทว่าผู้ดูแลยานพาหนะ)
6. เอกสาร: PDF หรือรูปภาพ ไฟล์ละไม่เกิน 10 MB ตามภาพอ้างอิง และสูงสุด 10 ไฟล์ตามที่ component ตั้งไว้ใน S26 (ภาพไม่ได้บอกจำนวน)
7. ค่าจ้างตรวจ: บังคับกรอก ยกเว้นเมื่อผลเป็นตรวจไม่ได้
8. ตรวจไม่ได้: ต้องระบุสาเหตุและแนบเอกสารยืนยัน คันนั้นปิดงาน แต่ไม่บันทึกเข้าทะเบียนและไม่เลื่อนวันครบกำหนด
9. ไม่ผ่าน และ ระงับ: เลื่อนวันครบกำหนดครั้งถัดไปเหมือนผ่าน ตามวิธีคิดเดิมของหน้า "การตรวจ ปจ.2"
10. วันที่ตรวจเลือกได้ไม่เกินวันนี้ และไม่บังคับให้อยู่ในช่วงวันทำงานของใบ
11. บันทึกผลแล้วแก้ไม่ได้
12. คอลัมน์ "ครบกำหนด" ในฟอร์ม และบรรทัดรอง "นัด" ใต้วันที่ตรวจ เป็นของที่เสนอเพิ่มจากภาพ
13. ข้อมูลจำลองใช้ยานพาหนะประเภท 09 ชุดเดิมของต้นแบบ ซึ่งมีทะเบียนในภาพอ้างอิง 1 อยู่แล้ว (เช่น 63-4569 ยะลา · 64-5097 กรุงเทพมหานคร · 70-1053 เชียงใหม่ · 72-6079 สระบุรี) จึงใช้คันเดียวกับภาพเท่าที่มี ส่วนวันที่ใช้รอบวันนี้ของต้นแบบ (10/11/2569) ไม่ใช้ปี 2570 ในภาพ
14. ผู้รับจ้างตรวจเป็นรายชื่อแยกจากผู้รับจ้างบำรุงรักษา
15. เลข scenario ชั่วคราว SI-E1 ถึง SI-E4
16. หน้า "การตรวจ ปจ.2" เดิมยังอัปโหลดผลนอกแผนได้ตามเดิม (ผล 3 ตัวเลือก PDF อย่างเดียว) ยังไม่ปรับให้ตรงกับ popup ใหม่
17. ความคืบหน้าเขียนว่า "ปิดงานแล้ว x/y คัน" นับคันที่ตรวจไม่ได้เป็นปิดงานแล้ว และบอกจำนวนคันที่ตรวจไม่ได้ต่อท้าย
18. สิ่งที่ต้องการจากแผนตรวจ: รหัสแผน ชื่อแผน สถานะ ช่วงเวลา หน่วยงานผู้สร้างแผน และรายการยานพาหนะพร้อมวาระรายคัน ผู้ทำส่วนสร้างแผนควรเห็นรายการนี้

## 10. เรื่องที่ต้องให้เจ้าของงานตัดสิน นอกงานเขียนหน้าจอ

- **ลิงก์สาธารณะ** branch อยู่บน GitHub แล้ว: https://github.com/anugmail/maintenance-utility-vehicle/tree/feat/safety-inspection-execution ส่วนเว็บต้นแบบสาธารณะ (GitHub Pages) deploy จาก `main` อย่างเดียว หน้าของงานนี้จะเปิดได้ที่ `https://anugmail.github.io/maintenance-utility-vehicle/safety/trips/` หลัง merge เข้า `main` ถ้าต้องการลิงก์ดูต้นแบบของแต่ละ branch ก่อน merge ต้องแก้ workflow deploy ซึ่งเป็นของกลางที่ทุกคนใช้ ยังไม่ทำจนกว่าเจ้าของงานจะสั่ง
- **เอกสารและการ์ด** ไฟล์ userflow จอ Figma เอกสาร Feature และการ์ด FLO ของเรื่อง Safety Inspection ยังไม่มี งานนี้ทำเว็บก่อนแบบเดียวกับ S26 จะอัปเดตที่ไหนและการ์ดใด ให้เจ้าของงานบอก
- **งานลบ comment ที่ค้างในโฟลเดอร์หลัก** ควร commit ขึ้น `main` ก่อนที่ทั้งสามส่วนจะเขียนโค้ดไปไกล เพราะทุก branch ต้อง rebase ตาม
